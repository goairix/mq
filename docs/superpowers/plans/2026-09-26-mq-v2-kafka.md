# MQ v2 Kafka 4.x implementation plan

> Execute on the user-designated `v2` branch. Apply TDD, local broker fault tests, and a fresh review before completion.

**Goal:** A separate `github.com/goairix/mq/adapters/kafka/v2` module for ordinary Kafka 4.x publish/consume. Root `go.mod` stays standard-library-only. Delayed Kafka publication composes with `delay/redis/v2` and is not in the normal adapter.

**Driver:** `github.com/twmb/franz-go` v1.21.6; this child module alone requires Go 1.25. No Kafka 3.x, ZooKeeper, or protocol fallback code.

**Production:** Use idempotent franz-go producer with `acks=all`, bounded application records/bytes, and per-record callback/confirm outcomes. Invalid messages reject before send; confirmation interruption returns unknown. Batch result order matches input. Ordinary `Publish` reuses the producer; no per-message client creation. Compression and broker replication are deployment options, not hidden core dependencies.

**Consumption:** One consumer group member per `Run`/`RunBatch`, explicit earliest reset by default, `DisableAutoCommit`, `BlockRebalanceOnPoll`, bounded fetch, and manual contiguous offset commits by partition only after handler success or confirmed DLQ publication. Rebalance cannot commit in-flight work. Retried records preserve original partition offset and key; cancellation drains within a configured bound, then abandons uncommitted work for redelivery. Each poll is processed within a documented rebalance timeout. `RunBatch` enforces logical batch count/byte/deadline and hard in-flight bytes; a single oversize record is rejected before handler.

**Failures:** Permanent handler failure is confirmed into a configured Kafka DLQ topic before the source offset commit. DLQ topic must exist with the desired replication/min ISR settings. Missing or unavailable DLQ blocks source commit. A publish confirm after commit failure can duplicate. Retention expiry is an operator-configured boundary, not something this module can prevent.

## Steps

1. Add child module, workspace entry, options, wire envelope, producer and unit tests. Run against Kafka 4.0.x KRaft.
2. Implement `Run` with manual commit, transient retry, permanent DLQ and drain; run portable contract and fault tests for missing DLQ, broker outage, group competition/fanout, restart and rebalance.
3. Implement `RunBatch` with contiguous per-partition commit, partial failures, strict batch bounds, and backlog tests.
4. Compare batch producer and consumer throughput/allocations with direct franz-go under identical broker/topic settings. Test on Kafka 4.0.x and a newer 4.x minor, run race and isolated dependency checks, document deployment/limits, request fresh review and fix Critical/Important findings.
